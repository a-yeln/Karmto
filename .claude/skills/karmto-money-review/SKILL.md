# ตรวจเงิน Karmto

## สูตรอ้างอิง (หาโค้ดจริงก่อนสรุปทุกครั้ง)
- P&L เดือน: `computeMonthFinancialsCore_` (~L5512), ช่วงวัน/กรองสาขา `computeRangeFinancials` (~L5603), แยกสินค้า `computePLBreakdown_`
- ต้นทุนล็อต: `lotCostTotal`, `lotCostPerKg`, `drawCostPerUnit_` (~L7613-7640) — ต้นทุนเข้า P&L เฉพาะส่วนที่ AY กดตัดแล้ว (`costedQty`)
- Brand fee: `computeFee` (~L2981), สาขาที่ยกเว้น `isFeeExempt` (branch.separate)
- หอยนางรม p7: ซื้อเป็น กก. ขายเป็นกระปุก — ระวังหน่วยปนกัน

## เช็คลิสต์ diff (ตอบ ผ่าน/ไม่ผ่าน/ไม่เกี่ยว + file:line)
1. ไม่มีการตั้ง `costedQty` > 0 โดยไม่ผ่านปุ่ม ✅ ตัด
2. ทุกการเขียนเป็น patch
3. ไม่แก้/ลบของที่จ่าย/ตัด/เคลมแล้วแบบเงียบ
4. เคารพ `closedMonths`
5. คีย์ใหม่อยู่ใน backup ทั้งสองที่
6. สูตรถูก — คิดเลขตัวอย่างจริง 1 เคสประกอบ (รวมปัดเศษ)
7. ไม่มี secret ในโค้ด
สรุป **ผ่าน** / **ไม่ผ่าน (ห้าม merge)**

## ป้าย "ไม่มีสินค้า" (day.noStock)
- ยอดบิล = ออเดอร์ × ราคา โดยช่องที่ `isNoStock_(d, code, pid)` เป็น 0 — เรียก `branchBillAmount(row, iso, d, code)` ครบ 4 ตัวเสมอ (ขาด d/code = นับสินค้าที่ไม่มีเป็นเงิน = ผิด)
- Brand fee: `computeFeeTotals(orders, d)` ไม่นับช่องไม่มีสินค้า · P&L แยกสินค้า/สาขา (`computePLBreakdown_`) ก็ไม่นับ
- จำนวนสั่งของ/ใบจัด/คาดการณ์ใช้ `computeTotals` (ตามออเดอร์); สต๊อก/ของเหลือ/ล็อต/ซื้อใช้ `shippedTotals_(d, iso)` (หัก ไม่มีสินค้า/ส่งขาด/ค้างส่ง + บวกส่งชดเชย) — ต้นทุนที่เบิกไปแล้ว AY แก้เองที่หน้าล็อต
- ส่งขาด: `day.shortQty[code][pid]` → จำนวนคิดเงิน = `deliveredQty_` (สั่ง − ขาด, ไม่ต่ำกว่า 0, ปัด 1 ตำแหน่ง); ไม่มีสินค้าชนะส่งขาด; fee/P&L ใช้ `billRow_`
- ค้างส่ง (บิลเต็ม): `backorders:YYYY-MM` — บิล/fee/ค้างโอนไม่เปลี่ยน; ห้ามซ้อนกับไม่มีสินค้า/ส่งขาดในช่องเดียวกัน; ค่าส่งชดเชย = รายจ่าย id `e-bo-<id>` หมวด ค่าส่ง/ลาล่า
