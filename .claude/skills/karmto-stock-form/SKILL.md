# ฟอร์มจดสต๊อกและการซิงค์

ไม่ใส่เลขบรรทัด — หาด้วย `grep -n "ชื่อฟังก์ชัน" index.html` (ทุกฟังก์ชันขึ้นต้น `sf`)
เรื่องที่สกิลอื่นอธิบายแล้ว: โครงล็อต/รอบเบิก/`costedQty` → **karmto-lot-costing** · กฎเขียนแบบ patch, ปิดเดือน → **karmto-iron-rules**

## ข้อมูลที่ใช้
- ร่างฟอร์ม `stockFormDraft` (root key, อยู่ใน `BACKUP_EXTRA_ROOT_KEYS`) + สำเนาในเครื่อง `karmto_stockform_draft`
  — `sfDraft = {from, to, opening, days:{iso:{pid:cell}}, done, synced, lastSyncAt}`; บันทึกอัตโนมัติด้วย `sfScheduleSave_`
- ตัวย้อนกลับของการซิงค์ล่าสุด `stockFormLastSync` (`SF_UNDO_KEY`) + สำเนาในเครื่อง
- ฟอร์ม**อ่าน**ข้อมูลระบบมาคำนวณ (`sfLoadCtx_`, `sfCompute_`) — ตัวช่วยกรอกแค่เติมช่อง ไม่เขียนลงระบบ (`stock-form-check-only.spec.js` ตรวจว่าไม่มีการเขียนเลย)

## ซิงค์ทำงานอย่างไร
1. **ขอบเขต** `sfSyncScope_`: เฉพาะวันที่ AY ติ๊ก "กรอกวันนี้ครบแล้ว" **ต่อเนื่องจากวันแรกของงวด** เริ่มจากวันแรกที่ยังไม่ได้ซิงค์
   วันที่ติ๊กแล้วแต่มีวันก่อนหน้าไม่ครบ = รอ (`waiting`)
2. **ดูตัวอย่าง** `sfCheck_` → `sfBuildPlan_`: เทียบฟอร์มกับข้อมูลสดทีละรายการ แล้วสร้าง op + op ย้อนกลับคู่กันทุกตัว
   - ต้นทุนซื้อสด: จับคู่ด้วยรหัสรายการ (`lineId`) แก้เฉพาะช่องที่ต่าง / เพิ่มใหม่ / ลบที่ฟอร์มเอาออก (ไม่แตะรายการ `fromLot`/`lotSettle`)
   - รอบเบิกล็อตใหม่: รหัส `sfd-<วันที่>-<สินค้า>-<ล็อต>` และ **`costedQty: 0` เสมอ** — AY ต้องไปกด ✅ ตัด เอง
   - รอบเบิกที่ตัดต้นทุน/เคลมแล้ว หรือข้อมูลเก่าที่ไม่มี `costedQty` = ล็อก ซิงค์ไม่แก้ให้ (AY แก้เองที่หน้าล็อต)
   - ของเสีย (ไม่รวมเคลม): รหัส `sfw-<วันที่>-<สินค้า>`; ของเสียที่ผูกล็อตแล้วไม่แก้ให้
   - ของเหลือปลายวัน: เขียนทีละช่อง `['leftoverOut', pid]` คิดต่อเนื่องจากวันแรกของงวด
   - ล็อตใช้เกินที่ซื้อ = error; บิลสินค้าล็อตปรับให้ยอดตรงกับล็อต
   - ยอดส่งที่แก้ในฟอร์มใช้คิดของเหลือเท่านั้น **ไม่แก้ออเดอร์**
   - วันในเดือนที่ปิดแล้ว = error (ต้องปลดล็อกในตั้งค่าก่อน)
3. **ซิงค์จริง** `sfSync_`: ถือกุญแจ `acquireLotSettleLock_` (กันชนกับการตัดต้นทุนจากเครื่องอื่น) → สร้างแผนใหม่จากข้อมูลสด
   ถ้า `sig` ต่างจากตัวอย่างที่ AY เห็น = หยุด ให้ดูตัวอย่างใหม่ → `sfApplyPlan_` เขียน rawLots → บิลล็อต → ของเสีย → ทีละวัน
   และบันทึกตัวย้อนกลับของแต่ละขั้นทันที (เน็ตหลุดกลางทาง = ย้อนส่วนที่เขียนไปแล้วได้)
4. **ประทับวันที่ซิงค์แล้ว** `sfDraft.synced[iso] = sfDaySig_(iso)` — แก้ฟอร์มวันนั้นทีหลัง ลายเซ็นไม่ตรง = วันนั้นกลับเป็น "ต้องซิงค์อีกรอบ" (ตั้งใจ ไม่ใช่บั๊ก)
5. **ย้อนกลับ** `sfUndo_`: ย้อนเฉพาะการซิงค์ล่าสุด ไล่ op ย้อนกลับจากหลังไปหน้า; ปฏิเสธถ้ารอบเบิกที่ซิงค์ไปถูกตัดต้นทุน/เคลมแล้ว

## ห้ามทำ
- ❌ ตั้ง `costedQty` > 0 ให้รอบเบิกที่มาจากฟอร์ม
- ❌ เปลี่ยนการเขียนเป็น "ลบทั้งวันแล้วเขียนใหม่" หรือ `set` ทั้งก้อน — ต้องจับคู่ด้วยรหัสและแก้ทีละรายการ
- ❌ ใช้รหัสสุ่มกับรายการที่ฟอร์มสร้าง — รหัสตายตัวทำให้กดซ้ำ/ลองใหม่แล้วไม่เกิดรายการซ้ำ
- ❌ เพิ่ม op ที่ไม่มี op ย้อนกลับคู่กัน
- ❌ ซิงค์โดยไม่ผ่านกุญแจ หรือข้ามการเทียบ `sig` กับตัวอย่าง

## เมื่อ AY บอกว่ายอดเพี้ยน
1. ถามวันที่ + สินค้า/ล็อตที่เพี้ยน (ห้ามเดา)
2. เทียบฟอร์มวันนั้นกับ 4 ที่: `purchases` ของวัน, `rawLots[].draws` (รหัส `sfd-`), `wasteRecords` (รหัส `sfw-`), `leftoverOut`
3. ดูว่าการซิงค์ล่าสุดยังย้อนกลับได้ไหม (`stockFormLastSync`)
4. รายงานความต่างก่อนแก้ — อย่าปรับตัวเลขให้ตรงเอง

## เทส
`stock-form-sync.spec.js` (ซิงค์เฉพาะวันครบ, รอบเบิกใหม่ไม่ตัดต้นทุน, รอบที่ตัดแล้วไม่แก้, ย้อนกลับ) และ `stock-form-check-only.spec.js` (ดูตัวอย่างไม่เขียนอะไร) ต้องผ่าน
แก้การซิงค์ → เพิ่มเคส: กดซิงค์ซ้ำ, เขียนล้มกลางทางแล้วย้อนกลับ, แก้วันที่ซิงค์แล้วต้องขึ้นว่าต้องซิงค์อีกรอบ
