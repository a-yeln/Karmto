# ศัพท์และกฎธุรกิจ Karmto

ไม่ใส่เลขบรรทัด (เลื่อนบ่อย) — หาด้วย `grep -n "ชื่อฟังก์ชัน" index.html` เสมอ
เรื่องที่สกิลอื่นอธิบายแล้ว **ไม่ซ้ำที่นี่**:
- ป้ายไม่มีสินค้า `noStock`, ส่งขาด `shortQty`, `billRow_`, `branchBillAmount` ต้องส่ง 4 ตัว, Brand fee → **karmto-money-review**
- โครงล็อต `rawLots`/`draws`/`costedQty`/`claimedQty`/`drawPendingQty_`/FIFO เคลม → **karmto-lot-costing**
- `costedQty: 0`, เขียนแบบ patch, ปิดเดือน → **karmto-iron-rules**

## สาขา

### แยกส่ง (`branch.separate`)
- สาขาเดียวกับสาขาเลขเดียวกันจริงๆ แค่แยกบิล/คนรับ (สั่งส่วนตัวโดยตรง)
- **กฎ (เจ้าของยืนยัน):** รหัสลงท้าย `T` = แยกส่งของสาขานั้น (`13T` คือสาขาเดียวกับ `13`); ไม่มี T = ส่งปกติ
- ในโค้ดตัดสินด้วยติ๊ก `separate` ในตั้งค่าเท่านั้น → `isFeeExempt(code)` (ดู "ต้องตรวจ" ด้านล่าง)
- มีผลกับ **Brand fee อย่างเดียว** (`computeFeeTotals` ข้าม) — ยอดบิล/รายได้/ค้างโอนยังนับเต็ม
- ❌ อย่าตัดสาขาแยกส่งออกจากยอดบิล/รายได้ ❌ อย่า hardcode รหัสเช็คแยกส่ง — เรียก `isFeeExempt(code)`

### แยกส่งอยู่ท้ายสุด
- **กฎ (เจ้าของยืนยัน):** ทุกลิสต์ที่มีหลายสาขา สาขาปกติก่อน (เรียงรหัส) แล้วแยกส่งต่อท้ายเป็นกลุ่ม; ภายในวันเดียวกันก็เช่นกัน
- ใช้ `branchEntrySortSeparateLast_` (entry `[code, ...]`) หรือ `outstandingCodeCmp_`; ข้อความม๊ะก๊าด/แจ้งหนี้มีหัวข้อ "แยกส่ง" คั่น
- ข้อความทวงทาง LINE: สาขาคู่ (ปกติ+แยกส่ง) รวมข้อความเดียว แบ่ง "บิลปกติ" > "บิลแยกส่ง" (`branchBaseNumber_`, `buildFollowupMessage_`)
- บั๊กเดิม: c8ba776 (แยกส่งปนกลางลิสต์), bce5054 (รวมกลุ่ม LINE ด้วยการตัดตัวอักษรท้าย → 1A/1B ปนกัน; ตอนนี้ตัดเฉพาะสาขาที่ติ๊กแยกส่ง)
- ❌ อย่าเรียงลิสต์สาขาด้วย `localeCompare` เปล่าๆ · spec: `separate-branch-sort-last.spec.js`

### นับสาขา "3+1"
- จำนวนสาขาที่สั่งในวันนั้น โชว์เป็น "ปกติ+แยกส่ง" (ไม่มีแยกส่ง = เลขเดียว ไม่ขึ้น "+0")
- ใช้ `branchCountLabel(orders)` (วันเดียว) / `branchSetCountLabel_(Set)` (ช่วงวัน) ทุกจุด: เฮดบาร์ แดชบอร์ด "ORDER N สาขา" ข้อความ
- บั๊กเดิม: 43615f7 (การ์ดช่วงวันยังโชว์เลขก้อนเดียว) · ❌ อย่านับ `Object.keys(orders).length` เอง

### สาขาที่มีแต่ "+ อื่นๆ" (custom ล้วน)
- ออเดอร์มีแต่ `row.custom` ไม่มี p1–p7 = **มีออเดอร์จริง มีเงินจริง**
- ความหมาย "สาขานี้มีออเดอร์ไหม" ต้องใช้ `orderRowHasOrder_(row)` เสมอ
  (ข้อยกเว้นที่ตั้งใจดูแค่แคตตาล็อก: ป้ายยกเว้น Brand fee และตัวจับออเดอร์ผิดปกติ — ตาม bce5054)
- บั๊กเดิม: bce5054 (~13 จุดเช็ค `PRODUCTS.some(...)` → สาขาหายจากรายได้/ข้อความหนี้/P&L/นับสาขา)
- ❌ อย่าเขียน `PRODUCTS.some(p=>row[p.id]>0)` เพื่อหมายถึง "มีออเดอร์" · spec: `custom-item-only-order-visibility.spec.js`

### สาขา 00
- ธงหมูกะทะ หลักสี่ (commit 2905c5a เรียก flagship store)
- **กฎ (เจ้าของยืนยัน):** คิด Brand fee ตามปกติ (ไม่ใช่แยกส่ง)
- ชื่อไม่มีคำว่า "สาขา": `branchDisplayName`/`branchBillLabel`/`branchAutoAddr` ใช้ `area`; ชื่อสั้น `branchShortLabel('00')` = "ธง";
  OCR เจอคำว่า "ธง" → รหัส 00 (`parseOcrText`)
- ❌ อย่าประกอบชื่อเอง `` `สาขา ${code}` `` — ใช้ฟังก์ชันชื่อด้านบน

## บิลและการทวงเงิน

### ยอดบิลสาขา + `billExtra`
- ยอดบิลจริงทุกจุด = `branchBillAmount(row, iso, d, code) + Number(d.billExtra[code]||0)`
- `billExtra` = ช่อง "ค่าใช้จ่ายเพิ่มเติม / เคลม (+/-)" ต่อบิล (เขียนด้วย `writeDayFieldPath_(iso, ['billExtra', code], …)`)
- ❌ อย่าลืม `+billExtra` ตอนคิดค้างโอน จับคู่สลิป ข้อความหนี้ หรือรายได้

### ค้างโอน / outstanding
- "รายการที่ต้องตามโอน" (`renderOutstanding`) = บิลที่ยอดข้างบน > 0 และ `day.billingPaid[code]` ว่าง
- ดู "ค้างโอน" = สแกนทุก `day:`; "โอนแล้ว/ทุกบิล" = จำกัดช่วงเดือน; ฟิลเตอร์ปกติ/แยกส่ง `outstandingTypeMatches_`
- จ่ายรวมหลายบิล: แต่ละบิลเก็บส่วนแบ่งตามสัดส่วน (`transferAmount`, `billedAmount` ของตัวเอง) + `batchId`/`batchCount`/`batchTotal`
  — บั๊กเดิม: 43615f7/bce5054 (ประทับยอดรวมลงทุกใบ) · spec: `billing-paid-stale-data-and-batch-split.spec.js`
- หลัง `writeBillingPaid_` ให้ใช้ document สดที่มันคืนมาแทน `dayData` เดิม (บั๊กเดิมเดียวกัน)

### รีเช็ค (`rchkm:` / `rchk:`)
- โหมดไล่เช็คทีละบิลก่อนทวง กันสาขาเอาสลิปเก่ามาอ้าง — เป็นชั้นบันทึกที่แยกจาก `billingPaid`
- `rchkm:<roundId>:<iso|code>` = ผลเช็คหนึ่งบิล (`found_paid`/`still_unpaid`); `rchk:<roundId>:<n>` = รอบที่ปิดแล้ว ชิ้นละ 100 บิล;
  `billingRecheckCurrent` = `{startedAt, roundId}`; ฟังก์ชัน `writeBillingRecheckMark_`, `clearBillingRecheckRound_`
- แยกคีย์เพราะช่อง Sheets รับ ~50k ตัวอักษร (43615f7); ทั้งสอง prefix อยู่ใน `BACKUP_PREFIXES`
- ❌ อย่ารวมผลเช็คกลับเข้าคีย์ก้อนเดียว

### ล็อกวันจ่าย (pay-date lock)
- `lastUsedPayDate` = วันที่จ่ายที่ใช้ล่าสุด เป็นค่าเริ่มต้นของช่องวันที่จ่ายทุกช่อง และอัปเดตทุกครั้งที่ยืนยัน
- ลิสต์ที่แพตช์ทีละแถว (ไม่เรนเดอร์ใหม่) ต้องเขียนวันที่ใหม่ลงช่องวันที่ของแถวที่ยังเปิดอยู่ด้วย
- บั๊กเดิม: be375c1 (ล็อกตามแค่การยืนยันครั้งแรก) · spec: `paydate-lock-follow.spec.js`

## ล็อต (ส่วนที่ karmto-lot-costing ไม่ได้อธิบาย)
- `qtyUsed` = กก.ดิบที่ดึงออกจากล็อต (หักคงเหลือล็อต, `totalCost = qtyUsed × lotCostPerKg`)
- `sellableQty` = "จำนวนที่ทำได้" (ขายได้หลังทำ) — ต้นทุน/หน่วย = totalCost ÷ (sellable − claimed) (`drawCostPerUnit_`)
- draw ที่**ไม่มี**ฟิลด์ `costedQty` = ข้อมูลเก่าก่อนมีระบบตัด → ถือว่าตัดครบแล้ว (ค้างตัด 0) — ห้ามเติม `costedQty` ให้ draw เก่า
- ตัดต้นทุนข้ามเครื่อง: อ่าน rawLots สดก่อน + กุญแจ `lotSettleLock` + rollback ด้วย delta (43615f7, `lot-settle-cross-device.spec.js`)
- claim-race: `ensureClaimsLinkedToLots_` ต้องกันเรียกซ้อน และเขียน `wasteRecords` ก่อน `rawLots` (`claim-race-fix.spec.js`)
- `fromLot`/`lotSettle` ในรายการซื้อ = ต้นทุนที่ตัดจากล็อต จ่ายไปแล้วตอนซื้อล็อต → ห้ามนับเป็นยอดค้างจ่ายผู้ขายซ้ำ (`filter(e=>!e.fromLot)`)
- `MONTH_LOCK_FREE_SET` = `paid`/`paidDate`/`paidAmount` ยังแก้ได้แม้เดือนปิด

## พฤติกรรมปัจจุบัน (ยังไม่ยืนยันว่าตั้งใจ — ห้ามถือเป็นกฎ ห้ามแก้เองถ้าไม่ถาม)
- `billExtra` แก้ได้แม้บิลนั้นติ๊กจ่ายแล้ว (handler ของ `[data-extra]` ไม่เช็ค `billingPaid`)
- `lastUsedPayDate` อยู่ในหน่วยความจำอย่างเดียว รีโหลด/เปลี่ยนเครื่อง = กลับเป็นวันนี้
- รีเช็คกด "เจอว่าโอนแล้ว" บนบิลค้าง → ระบบติ๊กจ่ายให้ด้วย `paidDate = วันนี้`, `transferAmount = ยอดบิล`

## ต้องตรวจ — ยังไม่แก้
- **ข้อเสนอเจ้าของ (ยังไม่ตัดสิน):** ให้ `13T` ต่อท้าย `13` ทันที (ไม่ใช่ไปท้ายลิสต์ทั้งหมด) — ตอนนี้กฎที่ใช้จริงคือ "แยกส่งอยู่ท้ายลิสต์" ห้ามเปลี่ยนจนกว่าเจ้าของตอบ
- **รหัส T vs S:** `DEFAULT_BRANCHES` ตั้งแยกส่งเป็น `13S`/`16S` (`separate:true`); spec ใช้ `13S`; คอมเมนต์เหนือ `branchBaseNumber_`
  เขียน "16 กับ 16T"; คอมเมนต์ใน `addBranch` พูดถึง 13T/16T — แต่**ไม่มีโค้ดใดดูตัวอักษรท้ายรหัส**เพื่อตัดสินแยกส่ง
  (grep `13T|16T|T'` เจอแค่คอมเมนต์) ⇒ รหัส `13T` ที่ไม่ได้ติ๊ก "แยกส่ง" ในตั้งค่า = ระบบนับเป็นสาขาปกติ (คิด Brand fee, ไม่ไปท้ายลิสต์)
  ต้องดูตั้งค่าจริงใน Sheets ว่ารหัส T ติ๊ก `separate` ครบไหม ก่อนจะแก้อะไร
- ปัดเศษสะสม (largest-remainder) ใน `confirmLotSettle_` อาจรวมต้นทุนของรอบเบิกคนละผู้ขายเข้าแถวก่อนหน้า (รายงานไว้ใน 43615f7) — ยอดรวมถูก แต่ผู้ขาย/จำนวน/ราคาต่อแถวอาจเพี้ยน
