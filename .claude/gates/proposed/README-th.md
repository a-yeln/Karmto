# ประตูกันรวมงาน (ร่าง) — **ตอนนี้ยังไม่เปิด**

> ไฟล์ทั้งหมดในโฟลเดอร์นี้เป็นร่างให้ AY ดูก่อน **ยังไม่มีอะไรทำงาน**:
> ไม่มี hook ถูกลงทะเบียน, ไม่มีไฟล์ใน `.github/workflows/`, ไม่มีใครเรียก `check-gates.js`
> จะเปิดเมื่อ AY บอก "เปิด" เท่านั้น

## มันทำอะไร (ภาษาง่าย)
ทุกครั้งที่จะรวมงาน (merge) เข้า `main` ประตูนี้จะเช็คว่า
**คนตรวจเงิน (money-guard) กับคนตรวจความปลอดภัย (security-guard) ได้ตรวจ "โค้ดชุดนี้จริงๆ" และให้ผ่าน** แล้วหรือยัง
- ถ้ายังไม่ตรวจ / ตรวจแล้วไม่ผ่าน / ตรวจไปแล้วมีคนแก้โค้ดต่อ → **ห้ามรวม** จนกว่าจะตรวจใหม่
- งานที่แก้แค่เอกสาร (ไม่แตะ `index.html` และ `backend/`) ใส่ "ไม่เกี่ยว" ได้ แต่ต้องเขียนเหตุผล
  และประตูจะเปิดดูรายชื่อไฟล์ที่แก้เอง — ถ้าแอบแก้ `index.html` หรือ `backend/` แล้วเขียนว่า "ไม่เกี่ยว" จะโดนบล็อก
- ถ้า guard ตัดสิน "ไม่ผ่าน" แล้วมีคนมาแก้คำเป็น "ผ่าน" โดยไม่ได้แก้โค้ด → บล็อก (ประตูเปิดดูประวัติไฟล์ผลใน PR)
- แถวอื่น (เทส, ui-checker, release ฯลฯ) ถ้าขาด → แค่ **เตือน** ไม่บล็อก (ตามที่ AY สั่งบังคับเฉพาะสองตัว)

### "ลายนิ้วมือ" คืออะไร ทำไมไม่ใช้ SHA
SHA ของ commit เปลี่ยนทุกครั้งที่ commit — พอ commit ไฟล์ผลด่านเข้าไป SHA ก็เปลี่ยนเอง (ไก่กับไข่)
เลยใช้ **ลายนิ้วมือ** = รหัส sha256 ของ "ส่วนที่ PR นี้แก้ทั้งหมด" โดย **ไม่นับโฟลเดอร์ `.claude/gates/results/`**
- เพิ่ม/แก้ไฟล์ผลด่าน → ลายนิ้วมือ **เท่าเดิม**
- แก้โค้ดอะไรก็ตามหลังตรวจ (แม้ตัวอักษรเดียว รวมถึงแก้ตัวตรวจเอง) → ลายนิ้วมือ **เปลี่ยน** = ต้องตรวจใหม่
- ดูลายนิ้วมือตอนนี้: `node .claude/gates/check-gates.js --fingerprint`
- ถ้า `main` มีงานใหม่ในไฟล์เดียวกับที่ PR แก้ แล้ว merge main เข้ามา ลายนิ้วมือจะเปลี่ยน (ต้องตรวจซ้ำ — ถือว่าถูก เพราะโค้ดที่จะรวมไม่เหมือนเดิม)
  ถ้า main เปลี่ยนแค่ไฟล์อื่น ลายนิ้วมือเท่าเดิม (เทสเคส 14)

### ไฟล์ผลด่านที่ต้องมีใน PR
`.claude/gates/results/<ชื่อ branch แทน / ด้วย ->.md` **ต้อง commit ขึ้นไปกับ PR** (ดูตัวอย่าง `result.example.md`)
เพราะ `.claude/gates/current.md` เดิมอยู่ใน `.gitignore` — GitHub มองไม่เห็น

## ตัวอย่างที่ AY จะเห็นตอนถูกบล็อก
บนหน้า PR ใน GitHub จะมีกากบาทแดงที่ช่อง **gates / guards** และกดดูจะเห็น:
```
⛔ บล็อก merge: ด่านเงิน/ความปลอดภัยยังไม่ครบ
  - security-guard ตรวจโค้ดชุดเก่า (ลายนิ้วมือ 4f1c9a0b7e22…) แต่โค้ดตอนนี้คือ 9a07c3d1e5b0… — มีการแก้หลังตรวจ ต้องให้ security-guard ตรวจซ้ำ
คำเตือน (ไม่บล็อก):
  - ไม่มีแถว ui-checker
ลายนิ้วมือโค้ดตอนนี้: 9a07c3d1e5b0...
ไฟล์ผลด่าน: .claude/gates/results/claude-example.md • ไฟล์โค้ดที่เปลี่ยน 1 ไฟล์ (แตะไฟล์เงิน/ระบบ: index.html)
```
ข้อความอื่นที่อาจเห็น: "ขาดแถว money-guard — ยังไม่ได้ตรวจ = ห้าม merge", "money-guard ตัดสิน "ไม่ผ่าน" — ห้าม merge",
"security-guard ใส่ "ไม่เกี่ยว" แต่ PR นี้แก้ index.html จริง", "ไม่มีไฟล์ผลด่านใน PR นี้"
ถ้าผ่าน: `✅ ด่าน money-guard + security-guard ครบและตรงกับโค้ดชุดนี้`

## ทางเลือก (ต้องเลือก 1)
| แบบ | กันอะไรได้ | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **ก. hook ในเครื่องอย่างเดียว** (บล็อกคำสั่ง merge ในเซสชัน Claude) | Claude กด merge เอง | ไม่ต้องตั้งอะไรใน GitHub, เด้งเตือนทันที | **ไม่กัน AY กด merge บนเว็บ**, ไม่กันเครื่องอื่น/เซสชันที่ไม่มี settings นี้, Claude แก้ settings ปิดเองได้ |
| **ข. CI อย่างเดียว + กฎป้องกัน main** | ทุกคนที่ merge ผ่าน GitHub (รวมเว็บ) — *เมื่อตั้งกฎแล้วเท่านั้น* | เป็นตัวจริงตัวเดียวที่กันการกดบนเว็บได้ | ต้อง commit ไฟล์ผล, ต้องตั้งกฎใน GitHub เอง, Claude รู้ว่าโดนบล็อกช้า (หลังเปิด PR) |
| **ค. ทั้งสองอย่าง** ✅ แนะนำ | ทั้งสองแบบ | hook เตือน Claude เร็วก่อนกด, CI เป็นด่านจริงที่กันเว็บ | ตั้งค่า 2 ที่ (แต่ใช้ตัวตรวจไฟล์เดียวกัน) |

**คำแนะนำ: แบบ ค.** เพราะ (1) ตามกติกา Claude เป็นคน squash merge เอง → hook จับได้ตั้งแต่ในเซสชัน ไม่ต้องรอ CI
(2) แต่ hook อย่างเดียวกัน AY/เว็บไม่ได้ — ด่านจริงต้องเป็น CI + กฎป้องกัน main (3) ทั้งคู่เรียก `check-gates.js` ตัวเดียวกัน กติกาไม่เพี้ยนกัน

## ข้อจำกัดที่ต้องรู้ (ไม่สัญญาเกินจริง)
- **hook ทำงานเฉพาะในเซสชัน Claude Code** ที่อ่าน `.claude/settings.json` ของ repo นี้ — ไม่ทำงานตอน AY กด merge บนเว็บ GitHub หรือในมือถือ
- **CI อย่างเดียวไม่กันการ merge** — มันแค่ขึ้นกากบาทแดง ปุ่ม merge ยังกดได้ จนกว่า AY จะตั้ง "กฎป้องกัน main" ให้ช่อง `guards` เป็นช่องบังคับ (งานค้างฝั่ง AY)
  และถ้าไม่ติ๊ก "ห้ามผู้ดูแลข้ามกฎ" เจ้าของ repo ยังกดข้ามได้
- ประตูเช็คว่า **ไฟล์ผลสอดคล้องกับโค้ด** — แต่ไม่ได้พิสูจน์ว่า guard ตรวจละเอียดจริง (ไฟล์ผลเป็นสิ่งที่ Claude เขียน) มันกัน "ลืม/ข้าม/แก้หลังตรวจ/กลับคำ" ได้ ไม่กัน "โกหกตั้งใจ"
- การกันกลับคำดูจากประวัติ commit ใน PR — ถ้ามีคน force-push ลบประวัติ จะกันข้อนี้ไม่ได้
- CI ใช้ตัวตรวจจาก `main` (PR แก้ตัวตรวจให้ตัวเองผ่านไม่ได้) แต่ไฟล์ workflow ที่ GitHub ใช้มาจาก PR — PR ที่แก้ `.github/workflows/` ต้องดูด้วยตา
- hook ตรวจ branch ที่เปิดอยู่ในเครื่อง — ถ้า Claude merge PR ของ branch อื่นโดยไม่สลับ branch ผลจะไม่ตรง (จะมีคำเตือนบอก)

## วิธีเปิดใช้ทีละขั้น (เมื่อ AY อนุมัติ — Claude ทำข้อ 1-2 ใน PR เดียว, ข้อ 4 AY ทำเอง)
1. ย้าย `check-gates.js` → `.claude/gates/check-gates.js`; ย้าย `gates-check.yml.disabled` → `.github/workflows/gates-check.yml`
2. อัปเดต `TEMPLATE.md` (คอลัมน์ "SHA ที่ตรวจ" → "ลายนิ้วมือที่ตรวจ" + คอลัมน์เหตุผล), ขั้นตอนใน `karmto-release-checklist`, `karmto-manager.md`, `ORG.md`, `CLAUDE.md`
   ให้ทุกรอบงานสร้างไฟล์ `.claude/gates/results/<branch>.md` แล้ว commit (PR นี้ต้องมีไฟล์ผลของตัวเองด้วย)
3. ดูผล CI 1–2 PR ว่าขึ้นถูก (ตอนนี้ยังกด merge ได้ เพราะยังไม่ตั้งกฎ)
4. **AY ตั้งกฎใน GitHub**: repo → Settings → Branches (หรือ Rules) → กฎของ `main` → เปิด "Require status checks to pass" → เลือกช่อง `guards`
   (แนะนำติ๊ก "Do not allow bypassing" ด้วย) — ข้อนี้ Claude ทำแทนไม่ได้
5. เพิ่ม hook: วางเนื้อหาจาก `hook-snippet.json` ต่อท้ายใน `.claude/settings.json` (ไม่ลบ hook เดิม) แล้วลองสั่ง merge PR ทดสอบ 1 ครั้งดูว่าโดนบล็อกจริง

## วิธีปิด / ย้อนกลับ
- **ด่วน (AY ทำเองบนเว็บ)**: Settings → Branches → กฎ `main` → เอาช่อง `guards` ออกจากช่องบังคับ → merge ได้ทันที
- ปิด CI: ลบ `.github/workflows/gates-check.yml` (หรือเปลี่ยนชื่อกลับเป็น `.disabled`)
- ปิด hook: ลบ 2 รายการที่เพิ่มใน `.claude/settings.json` (เหลือแค่ `pre-commit-check.sh` เดิม)
- ไฟล์ใน `.claude/gates/results/` ที่ค้างอยู่ไม่มีผลกับแอป ลบหรือเก็บไว้เป็นประวัติก็ได้

## เรื่องที่ต้องถาม AY ก่อนเปิด
1. นอกจาก `index.html` และ `backend/` จะให้นับไฟล์เหล่านี้เป็น "ต้องตรวจ ห้ามไม่เกี่ยว" ด้วยไหม:
   `.github/` (ตัวรันเทส/ด่าน), `.claude/settings.json`, `.claude/hooks/`, `tools/line-watcher/` — แนะนำให้นับ (เป็นเรื่องความปลอดภัย)
2. เก็บไฟล์ผลด่านของทุก PR ไว้ใน `main` เป็นประวัติ (ไฟล์ละ ~1 KB) ได้ไหม
3. เลือกแบบ ก / ข / ค

## ไฟล์ในโฟลเดอร์นี้
- `check-gates.js` — ตัวตรวจ (Node ล้วน) ใช้ได้ทั้ง CI (`exit 1` = บล็อก) และ hook (`--hook`, `exit 2` = บล็อก)
- `result.example.md` — ตัวอย่างไฟล์ผลด่าน (ข้อมูลสมมติ)
- `gates-check.yml.disabled` — ร่าง workflow (ยังไม่ทำงาน)
- `hook-snippet.json` — ข้อความที่จะเพิ่มใน `.claude/settings.json`
- `selftest.sh` — ทดสอบใน repo ชั่วคราว: `bash .claude/gates/proposed/selftest.sh <โฟลเดอร์ทดลอง>` (ผลล่าสุด 21/21 ผ่าน)
