# สไตล์ UI Karmto

- ธีม: `html[data-theme]` = mermaid / sea / neon / (ไม่มี = macaron); `data-tmode` = full / color; `data-bill`; เปลี่ยนผ่าน `applyTheme_` (~L12191) CSS อยู่ ~L952-1090
- ทุก UI ใหม่ต้องใช้สีจาก CSS variable ของธีม ห้ามฮาร์ดโค้ดสีที่อ่านไม่ออกในบางธีม
- มือถือ 420px ต้องไม่เลื่อนแนวนอน ปุ่มแตะง่าย (≥44px)
- แอนิเมชันแบบ AY: สมจริง/จำลองเหตุการณ์/อินโฟกราฟิกเคลื่อนไหวอธิบายแทนข้อความ — ไม่ใช่ตัวอักษรเด้ง; เคารพ `prefers-reduced-motion`
- สี AY: ชมพูพอดีๆ ตัดดำ/ขาว เริ่ดมีสไตล์ (แนวชมพู-ดำ) ไม่หวานจ๋า

## เช็คลิสต์แคปจอ
macaron, mermaid, sea, neon × tmode full/color ที่ 420px → ดูทีละภาพ: ล้นจอ • ตัวอักษรกลืนพื้น • ปุ่มทับ • แอนิเมชันกระตุก/วนไม่หยุด • ขัดสไตล์ AY

## ฟีดแบ็กหน้าตาที่ AY เคยให้ (ทำแล้ว — ใช้เป็นกฎกับงานใหม่)
- **การ์ดในกลุ่มเดียวกันต้องสีไม่ซ้ำกัน** ใช้ `data-tone` (sky/mint/lemon/pink/lav ...) ไม่ใช่สีเดียวทั้งหน้า — หัวข้อข้อความส่ง ORDER ก็สีไม่ซ้ำ
- **การ์ดในแถวเดียวกันต้องสมดุล** สูง/กว้างเท่ากัน ไม่โหว่ (เคยแก้: P&L, สรุปรายปี, Brand fee)
- **ของที่ควรอยู่บรรทัดเดียวกันต้องอยู่บรรทัดเดียว**: ดรอปดาวน์เดือนอยู่บรรทัดเดียวกับหัวข้อ (เดือนเป็นภาษาอังกฤษ ไม่เขียนคำว่า "เดือน"),
  กล่องไทล์ของเหลือเรียงแถวเดียว, ช่องสินค้า+ผู้ขายบรรทัดเดียวบน iPad/คอม, ปุ่มรองเป็นแท็บเล็กๆ ข้างช่องหมายเหตุ (เช่น ➕ เพิ่มในบิล / + อื่นๆ)
- **กระชับ**: ตารางรายการต้นทุนอ่านง่าย หน่วยรอง (เช่น "/หน่วย") ตัวเล็กกว่าตัวหลัก, ระยะบรรทัดแคบลง, มีแถวรวมท้ายตาราง
- **ปุ่มไอคอนในช่องกรอก** (เช่น 📋 ดึงยอดออเดอร์ในช่องจำนวนซื้อ) — ตัวช่วยแค่ "เติม" ห้ามบันทึกเอง
- **ธีมต้องต่างกันจริง** แต่เป็น design system เดียวกัน: โหมด color = เปลี่ยนแค่สี, full = เปลี่ยนเลย์เอาต์ด้วย; ทุกธีมมีบิลของตัวเอง (ไม่ใช่แค่เปลี่ยนสี)
  เลือกบิลได้ (`data-bill`) — ใบเสร็จ/ป้าย PeriPage ที่ส่งในแชทต้องอ่านง่ายทุกธีม
- **หัวแถบบนตรึง (📌) ต้องตรึงได้ทุกธีมทุกโหมด** — เคยพังเฉพาะ Sea full เพราะทับ `position:relative`; แก้ธีมแล้วเช็ค sticky ทุกครั้ง
- **มือถือห้ามล้นจอ**: กริดบนมือถือใช้ `minmax(0,1fr)` ไม่ใช่ `1fr`, ลูกของ grid/flex ที่มีตาราง/ข้อความยาวใส่ `min-width:0`,
  ตาราง `table.plain td` เป็น nowrap — ชื่อแถวยาวต้องเปิดให้ตัดบรรทัด, ตารางกว้างจริงใส่ใน `.scrollx`
- **อะไรที่ระบบทำแทนต้องเห็นชัด**: เช่น "รันสินค้าตัวถัดไป" ต้องกระพริบกรอบ + toast บอกชื่อสินค้าใหม่ + มีสวิตช์ปิด (เคยมีเคสสลับเงียบแล้วกรอกผิดสินค้า)
- **ฟอร์มที่กรอกค้างห้ามหายเมื่อแตะนอกฟอร์ม** (เก็บร่างไว้ เช่น `dashExpDraft_` ของรายจ่ายด่วน)
- **ป้าย PeriPage นุ่มนวล ไม่แข็ง**; ป้ายรวมทั้งวันหัวเป็น "ORDER" (ไม่เขียน "รวมทั้งวัน"); สาขาที่ตั้งป้ายชื่อเองไม่ขึ้นคำว่า "สาขา"
- **กราฟ**: แท่ง+เส้นคู่กัน เลื่อนซ้ายขวาได้ต่อเนื่อง ไล่สีสวย; แถวในศูนย์บัญชาการ/แจ้งเตือนแตะแล้วพาไปหน้าที่ต้องแก้
- แจ้งเตือน: ป้ายตัวเลขห้ามทับข้อความ, ชื่อเมนูเต็ม "Notifications"

- **ไม่มีราคา** — ใช้แปะกล่อง/เช็คของตอนแพ็ค (คอมเมนต์ ~L3469); ใบเสร็จเก็บเงินคือ `buildReceiptCardHTML` คนละใบ
- แถวสินค้า: **โชว์ PRODUCTS ครบ 7 ตัวเสมอ** ตามลำดับ PRODUCTS; ตัวที่ไม่สั่ง = ช่องจำนวนว่าง + แถวจาง (`.orderticket-row-unordered`);

  - ตั้ง "ป้ายชื่อกำหนดเอง" (`branchObj.label`) = ไม่ขึ้นคำว่า "สาขา" (`showSaxaKicker` ~L3480; abeac71, spec `ticket-custom-label-no-saxa`)

## 3) ปุ่มเรียง
- ปุ่มสลับข้อความบอกทิศทางเต็มประโยค: `⇅ ดีเลย์มาก→น้อย`/`⇅ ดีเลย์น้อย→มาก` (`#outstandingSortToggle`, ~L15063),
  `📅 เรียงตามวันที่` → `📅 ล่าสุด→เก่าสุด` → `📅 เก่าสุด→ล่าสุด` → ปิด (วน 3 สถานะ, `outstandingDateSortDir` ~L7406; ตอนเปิดอยู่ซ่อนปุ่มดีเลย์)
  — ข้อความปุ่มวันที่ตั้งใหม่ใน `renderOutstanding` ~L7715 ทุกรอบ (กันข้อความไม่ตรงสถานะเมื่อสลับโหมดรีเช็ค)
- รายบิลสาขา: `📅 ล่าสุด→เก่าสุด`/`เก่าสุด→ล่าสุด` ต่อสาขา (`branchDetailSortDir_` ~L12048; 23d6d0b)
- หัวตารางกดเรียง: `th[data-sorttopoutstanding]` สีเน้น + ` ▾` ที่คอลัมน์ที่เลือก (`renderTopOutstandingTable` ~L11838) ค่าเริ่ม `maxDelay`
- **ตัวตัดสินเสมอกันท้ายสุด = รหัสสาขา** แบบแยกส่งท้าย (`outstandingCodeCmp_` ~L7464) ห้าม `localeCompare` เปล่าบนลิสต์สาขา
- ▲▼ ใน "ตั้งค่า" (~L6391) คือ **จัดลำดับรายการ** (หมวด/คู่ค้า, "อื่นๆ" ปักท้าย `ensureOtherLast`) ไม่ใช่ปุ่มเรียง; ▲▼% ใน P&L คือลูกศรเทียบช่วงก่อน
- การจำค่า: ปุ่มเรียงทุกตัวตอนนี้เป็น **ตัวแปรในหน่วยความจำ** (รีโหลดกลับค่าเริ่ม) — ไม่มี localStorage และไม่เขียนลงข้อมูลร้าน
  ของที่จำต่อเครื่องใช้ `localStorage 'karmto.*'` ห่อ try/catch (theme, themeMode, billTheme, sidebarCollapsed, statBarCollapsed, purchAutoNext, motion, deviceName)

## 4) หลังกดยืนยัน: อัปเดตเฉพาะส่วน ห้าม reload
- ลำดับที่ใช้จริง (`toggleNoStock_` ~L5689, `setShortQty_` ~L5612, `confirmSlipMatch_` ~L5271):
  ต่อเน็ตไหม/คิวออฟไลน์ว่างไหม → ปิดเดือนไหม → ตั้ง busy + `btn.disabled` → **อ่านสด** `window.storage.get('day:'+iso)` → ตรวจ →
  เขียน patch (`writeDayFieldPath_`/`writeBillingPaid_`) → ตั้ง `dayData = saved` (ถ้า `iso===currentDate`) →
  เรียก render เฉพาะที่เกี่ยว (`renderBillingList(); renderStats(); renderFeeToday(); renderOutstanding(); renderBillingSummaryTiles()`) →
  `logActivity_` + `showToast` → `finally` ปลด busy (เช็ค `isConnected` ก่อนเปิดปุ่ม)
- ถูกบล็อกแต่ได้ของสดมา: อัปเดตแคช 3 จุด `dayCache_[iso]=fresh; writeDayToLocalStorage_(iso,fresh); dayData=fresh` แล้ววาดใหม่ (คอมเมนต์ ~L5285)
- ปุ่มกดแล้วจอไม่เปลี่ยน → พึ่งป้าย `✓ บันทึกแล้ว` (event `karmto-saved` ~L2510, เด้งตรงจุดที่แตะ, ไม่เด้งเมื่อเข้าคิวออฟไลน์/ล้ม) — ไม่ต้องทำ toast ซ้ำ
- งานยิงช้าซ้อนกัน: ใช้ตัวนับรอบ (`outstandingRenderSeq_` ~L7408) กันผลเก่ามาทับ "จอเด้งไปเด้งมา"
- ซิงค์จากเครื่องอื่น `syncFromOtherDevices_` ~L13669: ข้ามถ้า `userBusy_()` (กำลังพิมพ์/เปิด modal), จำ `scrollY` แล้วคืนหลังวาด + toast 🔄
- `location.reload()` มีแค่ 5 จุดใน 4 กลุ่ม: บันทึกรหัส API (~L13444 และช่องใส่รหัส ~L13463), เจอ `APP_BUILD` ใหม่และไม่ busy (`checkForAppUpdate_` ~L13653), ดูสแปลช, ปุ่ม "ลองโหลดใหม่" ตอนต่อฐานข้อมูลไม่ได้
  → **ฟีเจอร์ใหม่ห้ามเพิ่ม reload/ล้างทั้งหน้าหลังยืนยัน**; `window.scrollTo({top:0})` ใช้เฉพาะตอนเปิดฟอร์มแก้ ไม่ใช่หลังบันทึก

## 5) ข้อความไทยในแอป
- บล็อกเรื่องเงิน = บอกเหตุ + ทางแก้ + ย้ำว่า **"ยังไม่ได้…"**: `บิลสาขา X ติ๊กจ่ายแล้ว — ยกเลิกติ๊กจ่ายก่อน แล้วค่อย…`,
  `ยอดบิลเปลี่ยน ฿A → ฿B ยังไม่ได้ติ๊กจ่าย`, `เช็คข้อมูลล่าสุดไม่ได้ ยังไม่ได้เปลี่ยน`, `ต้องต่อเน็ตก่อน`, `เดือนนี้ปิดแล้ว แก้ไม่ได้`
- ระบบไม่แก้ให้ → ชี้หน้าที่ต้องไปแก้: `…ระบบไม่แก้ให้เอง แก้ที่หน้าเบิกล็อต…` (~L14594), `แก้ที่หน้าของเหลือ/ของเสียแทน` (~L14637)
- เน็ตไม่แน่ใจ: `ยังไม่แน่ใจว่าบันทึกหรือไม่ (เน็ตมีปัญหา?) ตรวจที่แถวบิลก่อนกดซ้ำ` (`confirmSlipMatch_`)
- เปลี่ยนค่า: ค่าเก่า `→` ค่าใหม่ ทั้งใน confirm (`แก้ยอด "เคลมไปแล้ว" … จาก A เป็น B` ~L10086) และบันทึกกิจกรรม
  (`ส่งขาด {สินค้า} {เก่า} → {ใหม่} สาขา X — บิลวันที่ dd/mm/yyyy`)
- กันแตะพลาดบนมือถือ: ปุ่มเดิมกด 2 จังหวะ (`btn.dataset.armed`, ข้อความ `⚠️ … — กดอีกครั้งเพื่อยืนยัน` ~L10121) หรือกดค้าง 1 วิ (`wireLotHold_`)
- เงิน `money()` ~L2420 = `฿1,234` ปัดเต็มบาท (ติดลบ `-฿`); วันที่โชว์ `formatDDMMYYYY` ~L2419 = `dd/mm/yyyy`, เก็บเป็น ISO

## ไม่แน่ใจ / ต้องถาม AY (ห้ามทำเป็นกฎเอง)
- ปุ่มเรียงควร **จำค่าต่อเครื่อง** (`karmto.*`) ไหม — ตอนนี้ไม่จำ ยังไม่เคยมีคำขอใน git
- ความกว้างแท็บเล็ตที่กดขยายควรจำไหม (ตอนนี้จำแค่จอกว้าง)
- confirm() ของเบราว์เซอร์ vs ปุ่ม 2 จังหวะ: เคยเปลี่ยนเพราะกดผ่านง่ายบนมือถือ (คอมเมนต์ ~L10121) แต่ยังเหลือ confirm() ~48 จุด — ใช้แบบไหนกับงานใหม่
- ชื่อเรียก "ตั๋ว/ใบจัดของ" ไม่มีในโค้ด — ยืนยันว่า AY หมายถึงป้าย PeriPage

## เช็คลิสต์แบบแผนก่อนส่งงาน UI (เพิ่มจากเช็คลิสต์แคปจอข้างบน)
1. แตะป้าย PeriPage/ใบรวม? ยังขาว-ดำ กว้าง 380 ไม่มีราคา ครบ 7 สินค้า และแยกส่งอยู่ท้าย
2. เพิ่มแท็บ? มีปุ่ม `data-tab` ใน sidebar (⚡ หาเจอเอง) + คำค้นใน `CMDK_TAB_KEYS`; ถ้าใช้บ่อยบนมือถือคุยเรื่องช่องใน `#mNav` ก่อน (มี 4 ช่อง)
3. ลิสต์หลายสาขาเรียงด้วย `branchEntrySortSeparateLast_`/`outstandingCodeCmp_`; ปุ่มเรียงบอกทิศเป็นคำ `ก→ข`
4. หลังยืนยัน: ไม่มี `location.reload`, render เฉพาะส่วน, แคช 3 จุดตรงกัน, ปุ่ม disable ระหว่างรอและเปิดคืนใน `finally`
5. ข้อความบล็อกมี "ยังไม่ได้…" + ทางแก้; ของที่แตะเงินโชว์เก่า → ใหม่ และจด `logActivity_`
6. เงินผ่าน `money()`/`moneyP()` วันที่ผ่าน `formatDDMMYYYY` ไม่ประกอบสตริงเอง
7. ค่าที่จำต่อเครื่องใช้ `localStorage 'karmto.*'` ใน try/catch — ห้ามเก็บสถานะหน้าจอลง `settings`/`day:*`
