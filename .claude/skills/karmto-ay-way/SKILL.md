# แบบฉบับ AY

อ่าน `.claude/ay-proxy/profile.md` เป็นแหล่งจริงเสมอ (ไฟล์นี้คือสรุป)

## AY ให้ความสำคัญ (เรียงตามลำดับ)
1. ตัวเลขเงินถูกเป๊ะ — สงสัยนิดเดียวให้หยุดถาม
2. สวย มีสไตล์ — แอนิเมชันแบบสมจริง/อินโฟกราฟิกเคลื่อนไหวแทนข้อความยาว (ไม่ใช่ตัวอักษรเด้ง); ชมพูพอดีๆ ตัดดำ/ขาว แนวชมพู-ดำ ไม่หวานจ๋า
3. ได้ของใหม่เร็ว — ส่งบ่อย แก้ทีหลังได้ (ยกเว้นเงิน)

## วิธีรายงาน
- ภาษาไทย สั้น ตรง บอกผลจริง: ผ่าน / ไม่ผ่าน / ยังไม่ได้ลองกับข้อมูลจริง
- ภาพ > ข้อความ: แนบ screenshot เมื่อเป็นงานหน้าตา
- เสนอสิ่งที่ควรมีได้เลย แต่ **ห้ามตัดฟีเจอร์ที่ AY ขอไว้เองโดยไม่ถาม**
- คำสั่งกำกวม → ทวนสั้นๆ ก่อนลงมือ
- แชทยาว/เปลี่ยนเรื่องใหญ่ → แนะนำเปิดเซสชันใหม่พร้อมข้อความเปิด

## ต้องถาม AY ตัวจริงเสมอ
เงิน/ต้นทุน/บิล/สต๊อก/เคลม/Brand fee • ลบหรือย้ายข้อมูล • ต่อระบบนอกหรือใช้ key/ค่าใช้จ่าย • เปลี่ยนหน้าตาใหญ่

## บทเรียนจากงานจริง (AY เคยท้วง)
- **"ทำก่อนจัดไป" / "ตามแผน"** แต่ไม่รู้ว่าแผนไหน → ห้ามเดาแล้วลงมือ: ถาม หรือหาในของที่ AY มี (artifact บน claude.ai เช่น แผน
  https://claude.ai/artifact/7CpfLeZ2MnjqXHZNE6U91y) — เคยเข้าใจผิดเริ่มทำ "ให้ Claude อ่านรูป" ทั้งที่ AY หมายถึงศูนย์บัญชาการในแผน
- **AY ถามว่า "ทำไมไม่แนะนำ"** = ต้องเสนอเองก่อน: แชทยาวจนถูกย่อความ → เสนอเปิดเซสชันใหม่ทันที; เห็นทางที่ดีกว่า → บอกเลย
- งานหลายข้อ → ทำครบทุกข้อที่สั่ง แล้วบอกตรงๆ ว่าข้อไหน "ทำไปแล้วก่อนหน้า" ข้อไหน "ยังไม่ได้ทำ" ไม่ปนกัน
- ถ้าบางข้อในแผนทำไม่ได้จริง (เช่น "เงินสดที่มีตอนนี้" ระบบไม่มียอดในบัญชีจริง) → ไม่เดาตัวเลข ใส่เท่าที่มีจริงแล้วบอกเหตุผล
- AY ส่งรูปหน้าจอพร้อมคำสั้นๆ (เช่น "การ์ดล้น") → จำลองบนจอขนาดเดียวกัน หาสาเหตุจริง แก้ แล้วไล่เช็คทุกหน้า/ทุกธีมว่าไม่มีที่อื่นเป็นแบบเดียวกัน
- ของที่ AY แนะนำมาเอง (repo/เครื่องมือภายนอก) → อ่านจริงก่อน แล้วตอบตรงๆ ว่าเหมาะไหม เสียเงิน/ส่งข้อมูลออกไหม ไม่เชียร์ตาม
- รูปแบบรายงาน: ประโยคแรกบอกผล (เสร็จ/ยังไม่เสร็จ/ขึ้นเว็บหรือยัง) → วิธีใช้สั้นๆ → ข้อควรรู้ (ยังไม่ได้ลองกับข้อมูลจริง ฯลฯ) → ถามต่อ 1 เรื่อง
