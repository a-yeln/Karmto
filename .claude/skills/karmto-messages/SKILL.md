# ข้อความส่ง LINE ของ Karmto

ไม่ใส่เลขบรรทัด — หาด้วย `grep -n "ชื่อฟังก์ชัน" index.html`
กฎที่สกิลอื่นอธิบายแล้ว **ไม่ซ้ำที่นี่**: แยกส่งอยู่ท้ายสุด / นับสาขา "3+1" / สาขาที่มีแต่ "+ อื่นๆ" / `billExtra` → **karmto-domain-glossary**

## แหล่งความจริงของรูปแบบ
- รูปแบบที่ AY ส่งจริงอยู่ในสกิลแชตของ AY (`taweechok-seafood-daily-order` = ข้อความสั่งของ, `taweechok-seafood-billing-transfers` = แจ้งหนี้/ทวงโอน)
  ถ้าเปิดได้ ให้เทียบทีละบรรทัดก่อนแก้; ถ้าเปิดไม่ได้ ให้ถาม AY ขอข้อความที่ส่งจริงหนึ่งวัน — **ห้ามเดารูปแบบเอง**
- ช่องว่าง/บรรทัดว่าง/อีโมจิ คือรูปแบบ ไม่ใช่การตกแต่ง — คนรับอ่านตามตำแหน่ง แก้แล้วต้องตรงทุกตัวอักษร

## การ์ด "💬 ข้อความส่ง" — `renderMessages()`
อยู่ในแท็บออเดอร์ สร้างจาก `dayData` ของวันที่เลือก เป็น 5 ส่วน (`blocks[].tag`):

| tag | หัวข้อ | สร้างจาก |
|---|---|---|
| `all` | สรุปยอดรวม | `computeTotals` ทุกสาขา (รวมแยกส่ง) + `ORDER ${branchCountLabel} สาขา`; p7 แสดงเป็น "กระปุก" |
| `mahkard` | สั่งม๊ะก๊าด | เฉพาะ p3 รายสาขา (`รหัส : จำนวน`) แยกส่งใต้หัวข้อ "แยกส่ง"; ยอดรวม = สั่ง − ของเหลือเมื่อวาน (`leftoverOut` ของวันก่อน) |
| `monk` | สั่งมนต์ | `MONK_IDS` (p1 p2 p4 p5 p7) ยอดสุทธิหักของเหลือเมื่อวาน; สินค้าที่วันนี้ไม่มีออเดอร์ = ตัดบรรทัดทิ้ง; อีโมจิ p1=✅ p2=❎ (`MONK_EMOJI_OVERRIDE`) ต่างจากส่วนสรุปโดยตั้งใจ |
| `phat` | พี่พัฒน์ | เชอรี่ (p6) สุทธิหักของเหลือ + "เหลือออก" จาก `LEFTOVER_SHORT` เฉพาะสินค้าที่วันนี้มีออเดอร์ |
| `debt` | แจ้งหนี้ | ทุกสาขาที่มีออเดอร์ `branchShortLabel(code) : ยอด` โดยยอด = `branchBillAmount(row, iso, d, code) + billExtra` ปัดเต็ม; แยกส่งใต้หัวข้อ "แยกส่ง" |

- ของเหลือที่หักคือของ **วันก่อนหน้า** (`loadDay(addDaysISO(currentDate,-1)).leftoverOut`) — ข้อความจึงขึ้น "(สั่ง X − เหลือจากเมื่อวาน Y)" เมื่อ Y > 0
- ปุ่ม 📋 คัดลอกทั้งหมด คั่นแต่ละส่วนด้วย `MSG_SEP` (เส้นยาว) เอาเฉพาะเนื้อหา
- คัดลอกส่วน `mahkard` หรือทั้งหมด → `markWorkflow_('supplierMsgAt')` (ติ๊กขั้น "สั่งของ" ในเช็คลิสต์วันนี้) — อย่าตัดออกตอนแก้ปุ่ม

### ข้อความที่ AY แก้เอง (`messageOverrides`)
- กด ✎ แก้แล้วบันทึก → `patchField('day:'+iso, ['messageOverrides', tag], text)`; รีเซ็ต → `patchOps` `deleteKey`
- มี override = แสดงข้อความที่แก้ไว้แทนข้อความอัตโนมัติ **ทั้งก้อน** (ขึ้น "(แก้ไขแล้ว)") — ข้อมูลออเดอร์ที่เปลี่ยนทีหลังจะไม่เข้าไปในส่วนนั้น
- `messageOverrides` อยู่ใน `MONTH_LOCK_FREE_FIELDS` (แก้ได้แม้เดือนปิด) — ❌ อย่าเปลี่ยนให้ override กลายเป็นตัวแก้ยอดเงิน

## ข้อความทวงโอนรายสาขา — `renderOutstandingLineMsgs_()` + `buildFollowupMessage_()`
- อยู่ในหน้าค้างโอน: สแกนทุก `day:` ที่บิล > 0 และยังไม่มี `billingPaid[code]`; ไม่รวมวันนี้ เว้นแต่ติ๊ก "รวมบิลของวันนี้ด้วย"
- รวมกลุ่มด้วย `branchBaseNumber_(code)`: สาขาปกติกับแยกส่งเลขเดียวกันอยู่ข้อความเดียว แบ่ง "📌 บิลปกติ" > "📌 บิลแยกส่ง"
- ข้อความขึ้นต้น "สวัสดีค่ะ จากบัญชีก้ามโตนะคะ" และปิดท้าย "พอดีเช็คในไลน์กลุ่มไม่มีสลิปส่งมาค่ะ รบกวนด้วยนะคะ 🙏🏻🥹"
- 3 แบบตามจำนวนบิล: 1 บิล = บรรทัดเดียว / หลายบิลชนิดเดียว = รายการ + "รวม" / มีทั้งสองชนิด = 2 หัวข้อ + "รวมทั้งหมด"
- ยอดใช้ `lineBaht_` (ปัดเต็ม คั่นหลักพันแบบไทย ไม่มี ฿)

## ก่อนแก้ข้อความ
1. เทียบกับข้อความที่ส่งจริง (ดูหัวข้อ "แหล่งความจริง") แล้วเขียนผลที่คาดไว้ใน spec ก่อนแก้โค้ด
2. ยอดเงินในข้อความต้องมาจากฟังก์ชันเดียวกับหน้าบิล (`branchBillAmount` + `billExtra`) — ❌ อย่าคิดยอดใหม่ในตัวสร้างข้อความ
3. spec ที่ครอบอยู่: `debt-message-per-branch.spec.js`, `separate-branch-sort-last.spec.js`, `custom-item-only-order-visibility.spec.js`,
   `workflow-supplier-order-step.spec.js`, `outstanding-filters-range-linemsg.spec.js` — แก้รูปแบบแล้วต้องอัปเดตข้อความที่คาดไว้ใน spec ด้วย
4. แก้รูปแบบที่ AY ใช้ส่งจริง → บอก AY ว่าสกิลแชต taweechok ตัวไหนต้องแก้ตาม (ผมแก้สกิลในบัญชีของ AY ไม่ได้)
