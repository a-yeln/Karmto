# ข้อความ LINE ของ Karmto

ไม่ใส่เลขบรรทัด (เลื่อนบ่อย) — หาด้วย `grep -n "ชื่อฟังก์ชัน" index.html` ก่อนแก้เสมอ
ไม่ซ้ำสกิลอื่น: แยกส่ง/`isFeeExempt`/นับ "3+1"/`branchBaseNumber_` ที่มาของบั๊ก → **karmto-domain-glossary** ·
สูตร `branchBillAmount` 4 ตัว/`noStock`/`shortQty` → **karmto-money-review** · บอท/`.gs` → **karmto-apps-script** · XSS/secret → **karmto-security-audit**

## 0) แหล่งความจริงของรูปแบบ
- รูปแบบที่ AY ส่งจริงอยู่ในสกิลแชตของ AY (`taweechok-seafood-daily-order` = ข้อความสั่งของ, `taweechok-seafood-billing-transfers` = แจ้งหนี้/ทวงโอน)
  ถ้าเปิดได้ ให้เทียบทีละบรรทัดก่อนแก้; ถ้าเปิดไม่ได้ ให้ขอข้อความที่ส่งจริงหนึ่งวันจาก AY — **ห้ามเดารูปแบบเอง**
- ช่องว่าง/บรรทัดว่าง/อีโมจิ คือรูปแบบ ไม่ใช่การตกแต่ง — คนรับอ่านตามตำแหน่ง แก้แล้วต้องตรงทุกตัวอักษร
- แก้รูปแบบที่ AY ใช้ส่งจริง → บอก AY ว่าสกิลแชต taweechok ตัวไหนต้องแก้ตาม (Claude แก้สกิลในบัญชีของ AY ไม่ได้)
- `messageOverrides` อยู่ใน `MONTH_LOCK_FREE_FIELDS` (แก้ได้แม้เดือนปิด) — ❌ อย่าให้ override กลายเป็นตัวแก้ยอดเงิน

## 1) แอปไม่ส่ง LINE เอง — แค่สร้างข้อความให้ AY คัดลอก
- ใน `index.html` ไม่มีลิงก์ `line.me`/`line://` และไม่เรียก LINE API เลย (grep แล้วไม่เจอ)
- ทุกปุ่มคือ "คัดลอก" = `navigator.clipboard.writeText` ถ้าไม่ได้ก็ใช้ textarea + `execCommand('copy')` สำรอง
  (`renderMessages`, `renderOutstandingLineMsgs_`, ปุ่มคัดลอกข้อความบิล, สรุปรีเช็ค)
  แล้วขึ้น toast เช่น "คัดลอกข้อความแล้ว — วางใน Line ได้เลย" + `logActivity_`
- รูปตั๋วออเดอร์/บิลใช้ `navigator.share({files})` = เปิดเมนูแชร์ของเครื่อง AY เลือกแอปปลายทางเอง
- บอท `backend/LineBot.gs` **เงียบ**: หัวไฟล์ L12 "ไม่ตอบ/ไม่ส่งอะไรในกลุ่มเด็ดขาด"; ส่งได้ทางเดียวคือ `linePushToOwner_` (LineBot.gs:434)
  ซึ่งรับเฉพาะ User ID รูปแบบ `U…32 hex` ของ AY และถูกเรียกจุดเดียว (LineBot.gs:351) ตอนมีคนพิมพ์ในกลุ่ม พร้อมคำเตือน
  "อย่าโอนเงินตามข้อความนี้"; ทาง intake ไม่เรียก LINE API ของคนอื่น (`docs/line-relay-for-it.md`)
- **กฎ:** ❌ ห้ามเพิ่มการส่ง/ตอบ LINE อัตโนมัติ (reply, push เข้ากลุ่ม, ส่งทวงตามเวลา) ❌ ห้ามบอทติ๊กจ่าย/บันทึกเงิน
  ✅ ข้อความใหม่ = สร้างข้อความ + ปุ่ม 📋 คัดลอก แล้วให้ AY วางเอง (ทำตามแพทเทิร์น clipboard + fallback ข้างบน)

## 2) โครงข้อความที่มีอยู่จริง

### 2.1 ทวงยอด/ติดตามโอนแยกสาขา — `buildFollowupMessage_`, `renderOutstandingLineMsgs_`
- ปุ่ม `#outstandingLineMsgBtn` "💬 ข้อความทวงยอดส่ง Line (แยกสาขา)" — 1 การ์ดต่อกลุ่มสาขา มีปุ่ม 📋 คัดลอก
- เลือกบิล: ทุก `day:` ที่ `billingPaid[code]` ว่าง และยอด `branchBillAmount(row, iso, d, code) + billExtra[code]` > 0
- ค่าเริ่มต้น **ไม่รวมบิลวันนี้** (`outstandingLineIncludeToday_`, ติ๊ก "รวมบิลของวันนี้ด้วย" ได้)
- รวมกลุ่มด้วย `branchBaseNumber_`: สาขาปกติ + สาขาแยกส่งเลขเดียวกัน = ข้อความเดียว; เรียงกลุ่มตามเลข; ในกลุ่มเรียงวันที่เก่า→ใหม่
- เงิน `lineBaht_` = ปัดเต็ม + คอมมา ไม่มี ฿ ตามด้วย "บาท"; วันที่ `formatDDMMYYYY` = DD/MM/YYYY
- 3 รูปแบบ: (ก) บิลเดียว → ประโยคเดียว "รบกวนเช็คสลิปยอดโอนบิล[แยกส่ง ]วันที่ … จำนวน … บาทค่ะ"
  (ข) หลายบิลประเภทเดียว → รายการ `•` + "รวม … บาท" (ค) มีทั้งสองประเภท → หัว `📌 บิลปกติ` ก่อน `📌 บิลแยกส่ง`
  แต่ละส่วนมี "รวมบิลปกติ/รวมบิลแยกส่ง" แล้วปิดด้วย "รวมทั้งหมด"
- ตัวอย่าง (ข้อมูลสมมติ, รูปแบบ ค):
```
สวัสดีค่ะ จากบัญชีก้ามโตนะคะ
รบกวนเช็คสลิปยอดโอนบิลตามนี้ค่ะ

📌 บิลปกติ
• วันที่ 05/10/2026 จำนวน 1,250 บาท
• วันที่ 07/10/2026 จำนวน 980 บาท
รวมบิลปกติ 2,230 บาท

📌 บิลแยกส่ง
• วันที่ 06/10/2026 จำนวน 450 บาท
รวมบิลแยกส่ง 450 บาท

รวมทั้งหมด 2,680 บาท
พอดีเช็คในไลน์กลุ่มไม่มีสลิปส่งมาค่ะ รบกวนด้วยนะคะ 🙏🏻🥹
```
- ที่มา: e0e4549 (สร้าง), bce5054 (รวมกลุ่มเฉพาะสาขาที่ติ๊กแยกส่ง ไม่ตัดตัวอักษรท้ายมั่ว)

### 2.2 การ์ด "ข้อความส่ง" รายวัน — `renderMessages` (5 ส่วน, ปุ่ม "📋 คัดลอกทั้งหมด" คั่นด้วย `MSG_SEP` เส้นยาว)
| ส่วน (tag) | หัว | แถว |
|---|---|---|
| สรุปยอดรวม `all` | `💢DD/MM/YYYY💢` → `ORDER {branchCountLabel} สาขา` | `{emoji}{ชื่อ} {รวม} {หน่วย}` ทุกสินค้า (p7 = กระปุก) |
| ม๊ะก๊าด `mahkard` | `🚩ออเดอร์ม๊ะก๊าด DD/MM/YYYY` | `{รหัสดิบ} : {p3}` ปกติก่อน → บรรทัดว่าง + `แยกส่ง` → แถวแยกส่ง; ท้าย `รวมทั้งหมด N กก.` (หักของเหลือเมื่อวาน ถ้ามีวงเล็บ "สั่ง X − เหลือจากเมื่อวาน Y") |
| มนต์ `monk` | `🚩ออเดอร์มนต์ DD/MM/YYYY` | เฉพาะสินค้าที่มียอด, หักของเหลือ, p1=✅ p2=❎ |
| พี่พัฒน์ `phat` | `🚩พี่พัฒน์` | `• เชอรี่ N` (ถ้ามี) + `• เหลือออก …` หรือ `-` |
| แจ้งหนี้ `debt` | `💢DD/MM/YYYY💢` → `ORDER {ป้าย} สาขา` | `{branchShortLabel} : {ยอดปัดเต็ม ไม่มีคอมมา/฿}` ปกติก่อน → `แยกส่ง` → แถวแยกส่ง (ไม่มีบรรทัดรวม) |
- ตัวอย่างแจ้งหนี้ (สมมติ): `💢05/10/2026💢` / `ORDER 2+1 สาขา` / `1 : 1375` / `2 : 825` / `แยกส่ง` / `13T : 550`
- ข้อความแจ้งหนี้เป็นก้อนเดียว (เคยลองแยกรายสาขาแล้วถอยกลับ ec42d0f; spec `debt-message-per-branch.spec.js`)
- คัดลอกส่วนม๊ะก๊าดหรือ "คัดลอกทั้งหมด" ติ๊กขั้น "สั่งของ" (`markWorkflow_('supplierMsgAt')`)
- แก้ข้อความเองได้ (✎) → เก็บ `day.messageOverrides[tag]` ด้วย `patchField` และ **ข้อความที่แก้ชนะข้อความอัตโนมัติ**
  มีป้าย "(แก้ไขแล้ว)" + ปุ่ม "รีเซ็ตเป็นข้อความอัตโนมัติ" (ลบด้วย `patchOps deleteKey`)

### 2.3 ข้อความบิล — ปุ่ม "คัดลอกข้อความบิล" (แท็บบิล และเช็คยอดรายสาขา)
- ผู้ขาย 4 บรรทัด → `บิลเงินสด #เลขบิล` (+ " (ส่งแยกบิล)" ถ้าแยกส่ง) → นาม/ที่อยู่จัดส่ง/เลขผู้เสียภาษีของผู้ซื้อ (ถ้ามีในตั้งค่า) → วันที่ →
  รายการ `{qty} {หน่วย} {ชื่อ} {ราคา} x {qty} = {ยอด}` (ส่งขาด/ไม่มีสินค้า = 0) → ผลรวมย่อย → ค่าใช้จ่ายเพิ่มเติม/เคลม →
  `รวมเงินทั้งหมด {money()}` + บาทตัวอักษร → `📌` หมายเหตุเคลม → `🦀…ขอขอบคุณ…🦀` → `№ เลขบิล • วันที่`
- ใช้ข้อมูลจาก `computeReceiptData` + ค่า extra ที่อยู่ในช่องตอนกด — ตรงกับบิลบนจอ

### 2.4 สรุปรอบรีเช็ค — `recheckRoundSummaryText_`
- `🔍 สรุปรอบรีเช็ค …` → `เช็คไป N บิล` → `• DD/MM/YYYY {branchName} {money()} — โอนแล้วจริง/ยังไม่โอนจริง (โน้ต)`

### รูปแบบเลขเงิน (ต่างกันตามชนิด ห้ามสลับเองโดยไม่ถาม)
- `money()` = `฿1,375` (บิล, รีเช็ค, หัวการ์ด) · `lineBaht_` = `1,375 บาท` (ทวงยอด) · แจ้งหนี้ = `Math.round` เปล่า `1375`
- `lineBaht_` ปัดทีละบิลและปัดยอดรวมแยกกัน → ผลรวมบรรทัดที่เห็นอาจต่างยอด "รวม" 1 บาทได้ถ้ายอดมีสตางค์

## 3) ข้อมูลที่ห้ามหลุด + ตัวเลขต้องมาจากสูตรเดิม
- ❌ ห้ามใส่ชื่อผู้โอน/เลขบัญชี/ข้อมูลจาก `lineInbox:`/`slipPayers` ลงข้อความที่จะส่ง — ข้อความทวงปัจจุบันมีแค่วันที่+ยอด
  (`buildFollowupMessage_` ไม่รับชื่อผู้โอน) และ `slipPayerHints_` แค่ติดป้ายบนปุ่มในแอป (CLAUDE.md); ตามข้อ 6 ของ karmto-security-audit
- ❌ ห้าม `console.log` ข้อความที่มีชื่อ/เลขบัญชี; ข้อความที่โชว์บนจอต้องผ่าน `escapeHtml` (`<pre>` ใน `renderOutstandingLineMsgs_`, karmto-security-audit ข้อ 1)
- ❌ ห้ามใส่ token/ลิงก์ `/exec`/รหัสใดๆ ในข้อความหรือในตัวอย่างใน repo (repo สาธารณะ — ORG.md)
- ข้อความบิลมีเลขผู้เสียภาษีผู้ซื้อ (ตั้งใจ มาจากตั้งค่าสาขา) — อย่าเพิ่มข้อมูลส่วนตัวอื่นเข้าไป
- ยอดต่อบิลทุกข้อความ = `branchBillAmount(row, iso, d, code) + Number(d.billExtra[code]||0)` —
  ❌ ห้ามคิดสูตรใหม่/รวมเอง ❌ ห้ามลืม `+billExtra` · "มีออเดอร์ไหม" ใช้ `orderRowHasOrder_` · แยกส่งใช้ `isFeeExempt` (glossary)
- นับสาขาในหัวข้อความใช้ `branchCountLabel` · ชื่อสั้นใช้ `branchShortLabel` (00 = "ธง") · ห้ามประกอบชื่อสาขาเอง

## 4) เช็คลิสต์ก่อนแก้ข้อความ
1. grep หาฟังก์ชันจริง + อ่าน diff ของ e0e4549/bce5054/ec42d0f ถ้าแตะทวงยอด/แจ้งหนี้
2. เทสที่ต้องรันและอัปเดต:
   `outstanding-filters-range-linemsg.spec.js` (ข้อความทวง: ข้อความเดียวต่อคู่ปกติ+แยกส่ง, คำทักทาย/คำปิด, รวมส่วน, ประโยคบิลเดียว) ·
   `debt-message-per-branch.spec.js` (ก้อนเดียว, "แยกส่ง" คั่น, `ORDER 2+1`, ไม่มี "+0", แก้ข้อความ override) ·
   `separate-branch-sort-last.spec.js` (ลำดับม๊ะก๊าด/แจ้งหนี้) · `workflow-supplier-order-step.spec.js` (ติ๊ก "สั่งของ" + ไม่ `set` ทั้งวัน) ·
   `layout-noti-leftover-tiles.spec.js` · บอท: `line-bot-backend.spec.js`, `line-intake-backend.spec.js`
   — เปลี่ยนถ้อยคำ = เทสที่เช็คข้อความตรงตัวจะแดง ต้องแก้เทสพร้อมกันและบอก AY ว่าเปลี่ยนคำ
3. เทียบเลข: ยอดแต่ละบรรทัดในข้อความทวง = ยอดแถวในรายการค้างโอน/บิลที่เปิด (รวม billExtra, ไม่มีสินค้า, ส่งขาด);
   แถวแจ้งหนี้ = ยอดรวมบิลสาขาวันนั้น; ข้อความบิล "รวมเงินทั้งหมด" = `grandtotal-{code}` บนจอ
4. ลองเคส: บิลเดียว / หลายบิลประเภทเดียว / ปกติ+แยกส่ง / สาขามีแต่ "+ อื่นๆ" / สาขา 00 / วันไม่มีแยกส่ง / มี `messageOverrides` ค้าง
5. ไม่เพิ่มการเขียนข้อมูลจากการกดคัดลอก ยกเว้น `markWorkflow_` เดิม; ไม่เพิ่มการส่งออกนอกเครื่อง

## ไม่แน่ใจ / ต้องถามเจ้าของ
- น้ำเสียง: มีหลักฐานแค่คำในโค้ด ("สวัสดีค่ะ จากบัญชีก้ามโตนะคะ", "รบกวน…ค่ะ", "🙏🏻🥹") — คำอื่น/ข้อความชนิดใหม่ถาม AY ก่อน
- ทำไมแจ้งหนี้ใช้เลขไม่มีคอมมา และม๊ะก๊าดใช้รหัสดิบ (`01`) แต่แจ้งหนี้ใช้ `branchShortLabel` (`1`) — ตั้งใจหรือไม่ ยังไม่ยืนยัน
- override ที่แก้ไว้ไม่อัปเดตตามยอดที่เปลี่ยนทีหลัง — ควรเตือนไหม (ยังไม่มีในโค้ด)
- โน้ตอิสระในสรุปรีเช็ค (`it.note`) อาจมีชื่อผู้โอน — ควรกรองไหม
